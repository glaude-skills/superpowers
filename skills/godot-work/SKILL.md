# Godot 작업 규칙

Godot 를 돌리는 일(테스트, 캡처, 가져오기, 내보내기, 영상 뽑기, Blender 굽기처럼 GPU 와 CPU 를 오래 쓰는 일)의 규칙이다. 세션과 서브에이전트 모두 따르고, 에이전트에게 Godot 일을 맡길 때는 브리프에 이 스킬을 적는다.

## 무거운 일은 하나씩

- Godot 명령은 공유 잠금 디렉터리를 잡고 하나씩 돌린다: `until mkdir <잠금 경로> 2>/dev/null; do sleep 20; done; <명령>; rmdir <잠금 경로>`. 잠금 경로는 프로젝트 문서가 정한다(없으면 `~/.claude/heavy.lock`)
- 잠금은 명령 하나만큼만 잡는다. 테스트 파일 여럿은 한 번 잠금 안에서 for 문으로 차례로 돌리고 파일마다 결과 한 줄(Passing, Failing)만 출력한다. 실패한 파일만 자세히 본다
- 명령이 끊기면 남은 Godot 프로세스와 잠금부터 치운다
- 나란히 도는 에이전트를 늘려도 Godot 일은 잠금에서 다시 한 줄로 선다. 빨라지는 것은 읽기와 코드 쓰기가 겹칠 때뿐이다

## 테스트 (fork policy, 2026-11-21)

- **에이전트는 전체 테스트를 돌리지 않는다.** 그 변경이 닿는 테스트(고친 파일을 쓰는 테스트를 grep 으로 찾는다)와 계획의 회귀 가드만 돌린다
- **조정자(세션)도 전체 테스트를 늘 돌리지 않는다.** 머지할 때마다 그 머지가 바꾼 파일에 닿는 테스트만 고른다: 두 sha 사이에 바뀐 테스트 파일, 그리고 바뀐 스크립트, 셰이더, 리소스의 `res://` 경로나 `class_name` 을 쓰는 테스트 파일(프로젝트의 고르는 도구, 예 `tools/impact_tests.sh <기준 sha>`, 없으면 만든다). 머지 여럿을 몰아서 고르면 겹쳐 거의 전체가 되니 머지마다 바로 돌린다
- **전체 테스트는 셋일 때만:** 남에게 줄 빌드(데모, 출시, 상점 캡처) 앞, 하루 한 번 잠금을 기다리는 에이전트가 없을 때, 고른 테스트가 전체의 70% 를 넘을 때. 사람이 기다리는 일(빌드, 판정 캡처)이 잠금 줄에 있으면 전체 테스트보다 앞에 세운다
- 깨진 것이 나오면 바로 고치거나, 그 코드를 아는 도는 에이전트에 붙이거나, 고칠 에이전트를 띄운다
- 까닭: 한 세션에서 에이전트 하나가 다른 에이전트들의 전체 테스트 뒤에 줄 서서 64분을 기다렸고, 전체 테스트 한 번이 약 70분 잠금을 잡았다. 머지 넷의 뒤 전체 테스트에서 깨진 둘은 머지마다 고른 테스트(전체 300 가운데 37 ~ 149개)에도 모두 들어 있었다. 대가는 두 변경이 서로를 깨뜨린 것을 머지 뒤에 알게 된다는 것이다. 경민님 확인("그 규칙은 Godot 작업 규칙 md 파서 거기 테스트 규칙으로 수퍼파워에 넣어둬", 2026-11-21)
- 테스트를 먼저 쓰고 붉은 판을 본 뒤 고친다(superpowers:test-driven-development)
- 테스트 실행기가 테스트 0개나 지정한 파일 없음을 통과로 돌려주는지 확인한다(GUT 는 그렇다). 프로젝트의 감싼 스크립트가 있으면 그것만 쓴다

## 기다리기

- 10분 안에 끝나는 명령은 전경에서 Bash timeout(최대 600000)으로 한 번에 돌린다
- 더 긴 명령(봇 테스트, 영상 뽑기)은 뒤에서 한 번 돌리고 끝 알림만 받는다. 출력 파일을 들여다보지 않는다. 깰 때마다 맥락 전체를 다시 읽는다

## 워크트리와 캡처

- 새 워크트리는 처음에 `--headless --import` 를 한 번 한다. 새 `class_name` 을 더한 뒤에도 한 번 더 한다
- 이어받는 에이전트는 가능하면 앞 에이전트의 워크트리를 그대로 쓴다(가져오기를 다시 하지 않는다)
- 화면 판정 캡처는 실제 창(헤드리스 아님)에서 정한 해상도로 찍는다. 에이전트는 판정에 꼭 필요한 다섯 장 안에서만 그림을 읽고, 나머지는 사람이 볼 폴더로 복사만 한다
- 실행 중에 재질의 셰이더 조합(bool, int 칸)을 바꾸지 않는다. 세기와 색만 바꾼다. 처음 쓰는 조합은 멈춤(스터터)을 낸다
