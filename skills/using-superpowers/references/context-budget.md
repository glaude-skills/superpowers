# 상시 로딩 문서 법칙 (fork policy, 2026-11-24)

경민님이 2026-11-24 에 승인한 전체 법칙이다. 한 백엔드 프로젝트의 하네스 규칙(상시 로딩 비용, 라우팅 표, 줄 수 래칫, 목록 파일 금지, 정합성 게이트)을 superpowers 의 모든 스킬과 모든 프로젝트에 적용한다. `../SKILL.md` 의 "상시 로딩 법칙" 절이 한 줄 요약이고, 이 파일이 상세와 근거다.

## 1. 상시 로딩 범위와 비용

| 상시 로딩 파일 | 읽히는 때 | 상한 |
|---|---|---|
| `skills/using-superpowers/SKILL.md` | SessionStart hook 이 startup, clear, compact 때마다 통째로 넣는다 | 9,000자, 20 KB |
| 각 스킬의 `SKILL.md` | 스킬을 호출할 때 통째로 읽힌다 | 40 KB. 넘으면 `references/` 로 나눈다 |
| 프로젝트 `CLAUDE.md`, `CONTEXT.md` 와 그 `@` import | 매 세션과 매 서브에이전트 시작 | `scripts/context-check` 기본값 120줄, 48 KB. 프로젝트가 정한 값이 우선한다 |

이 파일들의 한 줄은 매 세션, 매 서브에이전트가 호출할 때마다 다시 읽는 비용이다. 한 프로젝트에서는 새 세션이 작업을 시작하기 전에 약 100k 토큰에 이르렀고, 그중 3분의 1이 라우팅 파일 하나였다.

**hook 출력 상한.** Claude Code 는 hook 의 `additionalContext` 와 stdout 을 문자열마다 10,000자로 제한한다. 넘으면 전체를 세션 폴더의 파일로 저장하고 모델에는 앞 2,000자 미리보기와 파일 경로만 넘긴다. 모델에게 그 파일을 읽으라고 지시하지 않고, 상한을 올리는 설정도 없다. using-superpowers 가 54.7 KB 이던 6.4.96 까지는 모든 세션이 언어와 문체 절 앞부분만 받았다. 작업 기록, 에이전트 `model` 과 `effort` 표, clear 와 compact 권고, 인계 규칙은 전혀 전달되지 않았고, 플러그인을 다시 불러와도 같은 hook 이라 결과가 같았다.

SKILL.md 상한 9,000자는 hook 이 앞뒤에 붙이는 문구(약 250자)와 경고 한 줄을 더해도 10,000자 안에 들도록 정한 값이다. 문자는 UTF-8 코드 포인트 수로 센다(한글 한 글자가 1자). 바이트 상한 20 KB 는 영어 문단이 늘어 바이트가 먼저 커지는 경우를 막는다.

## 2. 상시 로딩 파일에 두는 것

- 전역 규칙과 링크 한 줄만 둔다. 기능 동작, 경로, 수치, 결정, 이력은 프로젝트에서는 `docs/work/<slug>/`, 스킬에서는 그 스킬의 `references/` 가 소유한다.
- 같은 내용의 요약 절을 따로 두지 않는다. 요약과 원문이 함께 있으면 시간이 지나며 어긋난다. 한 프로젝트에서는 요약이 원문과 다른 사례가 6건 나왔다.
- 상시 로딩 파일 안에서 다른 문서를 가리킬 때는 경로를 백틱으로 쓴다. Claude Code 는 코드 스팬 밖의 `@경로` 를 줄 중간에 있어도 import 하므로, 필요할 때 읽을 문서가 상시 로딩으로 바뀐다.

## 3. 상한과 래칫

- 상한을 올려 자리를 만들지 않는다. 새 규칙은 같은 만큼 줄이거나 문서 하나를 라우팅 표로 내릴 때만 넣는다.
- 줄 수를 줄였으면 상한도 그만큼 내린다(여유 0). 바이트 예산은 정상 편집 하나가 통과할 만큼 여유를 두고, 상세가 쌓이는 추세에서 실패하게 정한다.
- 바이트로 재면 로케일과 무관하게 같은 값이 나온다. UTF-8 에서 바이트 수는 문자 수 이상이므로 바이트 상한 N 은 문자 N 이하를 보장한다. hook 출력처럼 문자로 정해진 한도는 문자로도 잰다.

## 4. 라우팅 표

상시 로딩 파일 안에 3열 표를 둔다.

| 트리거 (사용자 말, 작업, 경로) | 먼저 읽을 파일 | 잊으면 안 되는 한 줄 |
|---|---|---|

- 표 머리에 "트리거에 해당하면 요청이 없어도 일을 시작하기 전에 읽는다" 를 둔다.
- 세 번째 칸은 요약이 아니다. 그 파일을 읽지 않고 일해도 가장 비싼 실패를 막는 한 줄이다. 한 줄과 원문이 다르면 원문을 따른다.
- 필요할 때 읽는 파일마다 한 행 이상을 둔다. 표에 행이 없는 파일은 아무도 읽지 않는다(고아 문서).
- 서브에이전트는 표를 받지 못한다. 구현이나 리뷰 에이전트를 디스패치할 때는 이 표를 변경 경로에 적용한 문서 목록을 브리프에 넣는다.

## 5. 상세를 옮기는 법

- 문장 그대로 옮기고 링크만 고친다. 옮기면서 문장을 다듬으면 의미가 바뀐 곳을 리뷰가 찾지 못한다.
- 옮긴 뒤에는 원문과 새 파일들의 줄 집합을 비교해, 빠진 줄이 없고 바뀐 줄은 링크 수정뿐인지 확인한다.
- 옮긴 절을 이름으로 가리키던 다른 파일의 인용(예 "using-superpowers, Work Records")도 새 경로로 고친다. 절 이름에 기대는 인용은 끊겨도 아무 오류가 발생하지 않는다.

## 6. 모든 브랜치가 같은 자리에 쓰는 파일 금지

공유 목록 파일은 모든 브랜치가 같은 끝에 한 줄씩 더하므로 머지할 때마다 충돌한다. 한 프로젝트에서는 기준 브랜치 재병합 19건 중 기술 부채 목록 파일에서 14건, 작업 색인에서 10건, `CLAUDE.md` 이력 표에서 10건의 충돌이 발생했다. 그래서 항목당 파일로 둔다.

| 기록 | 위치 | 목록을 뽑는 방법 |
|---|---|---|
| 작업 진행 | `.ai/status/<slug>.md` | `ls .ai/status` |
| 기술 부채 | `docs/tech-debt/<영문-요약>.md`, frontmatter `status: open` 또는 `resolved` | `grep -l '^status: open' docs/tech-debt/*.md` |
| 변경 이력 | `docs/changelog/YYYY-MM-DD-<slug>.md`, frontmatter `date`, `category` | `ls docs/changelog` (날짜 접두라 이름순이 날짜순이다) |
| 작업 문서 | `docs/work/<slug>/` | `ls docs/work` |

- 손으로 유지하는 색인과 진입 파일 끝의 이력 표를 두지 않는다. 색인을 다시 만들면 그 색인이 같은 자리가 된다.
- 해소한 부채 파일은 지우지 않는다. `status: resolved` 로 바꾸고 근거 한 줄을 남긴다.

## 7. 게이트로 강제

- 죽은 참조, 고아 문서, 상한 초과를 검사하는 스크립트를 두고 커밋 전에 돌린다. 프로젝트에 lint 나 pre-push 단계가 있으면 거기에 연결한다.
- 위반은 한 번에 모두 보고한다. 하나씩 고치고 다시 돌리게 하면 게이트를 우회하게 된다.
- 실패 메시지에는 그 검사를 두는 까닭과, 의도해서 없애려면 무엇을 해야 하는지(제거 조건)를 함께 쓴다.
- 예외를 조용한 목록으로 두지 않는다. 예외마다 `docs/tech-debt/` 항목을 둔다.
- 프로젝트용 게이트는 이 스킬의 `scripts/context-check` 다(누락 import, 줄 수, 바이트, 고아 문서, 진입 체인의 죽은 문서 경로). 프로젝트에 자체 게이트가 있으면 그것을 유지하고, 그 게이트가 검사하지 않는 것만 이 스크립트로 검사한다.
- superpowers 저장소에서는 `tests/claude-code/test-skill-context-budget.sh` 가 using-superpowers 상한, `references/` 경로 실재와 고아, 스킬별 40 KB 상한을 검사하고, `tests/hooks/test-session-start.sh` 가 hook 출력 10,000자 상한을 검사한다. 스킬을 고친 커밋 전에 둘 다 돌린다. hook 도 상한을 넘으면 출력 맨 앞에 경고를 붙여, 잘린 사실이 미리보기 안에 보이게 한다.

## 8. 스킬에도 같은 원칙

- 자동으로 로딩되는 범위는 작게 두고 상세는 `references/` 로 옮긴다. SKILL.md 에는 절차의 단계와 라우팅 표를 두고, 단계 중간에 드물게 필요한 절(예시, 합리화 표, 모델 선택, 예산 상세)은 문장 그대로 `references/` 로 옮긴다.
- SKILL.md 가 40 KB 를 넘으면 나눈다. 6.4.98 에서 using-superpowers(54.7 KB)와 subagent-driven-development(47.2 KB)를 나눴다.
